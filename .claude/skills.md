# 徐州110 kV容载比弹性指标优化研究报告修改润色 Skill

## 1. Skill目标

本 Skill 用于对本项目研究报告进行正式化、工程化、学术化修改。

修改目标不是重新撰写报告，也不是改变既有模型，而是在**保持原始研究逻辑、数据、结论、章节结构和Word排版体系不变**的前提下，完成以下工作：

1. 清除程序代码、脚本变量、数据库内部字段等不适合直接出现在正式研究报告中的表达；
2. 修正不规范或物理含义不清楚的公式；
3. 统一容载比、承载力、源荷比、电量渗透率、同步净负荷、正向/反向潮流等核心术语；
4. 修正过度技术化、口语化、开发文档化的语言；
5. 检查公式、正文、表格、图题及图片内部文字是否一致；
6. 保持报告的工程研究属性，不把项目报告改写成纯学术论文；
7. 不因润色擅自增加模型、数据、结论、政策要求或标准阈值。

# 2. 总体修改原则

执行时始终遵循以下优先级：

> **科学与工程含义正确 > 指标口径一致 > 数据事实不变 > 语言正式 > 版式美观**

任何语言修改都不得破坏前四项。

## 2.1 禁止“只润色句子，不检查物理含义”

发现公式、指标、变量或结论存在逻辑问题时，必须先处理科学含义，再调整文字。

例如：

原式：

`R(p,y,v)=S(p,y,v)/P_max^+(p,y,v)`

若该处是在定义“容载比”这一通用指标，则不应因为程序中存在不同优化路径，就把 `p` 强行写入容载比的基础定义。

应先恢复正式指标定义，再在优化章节说明不同方案分别计算该指标。

# 4. “路径”一词的特殊处理规则

本项目的优化分析确实存在不同规划路径，因此“路径”不是禁用词。

但必须区分两类情况。

## 4.1 可以使用“路径”的地方

用于描述多年规划方案时：

- 实际发展路径；
- 弹性优化路径；
- 严格优化路径；
- 2022—2025年规划路径；
- 不同规划路径的累计年化成本。

## 4.2 不应引入“路径变量”的地方

基础指标定义中原则上不要加入 `p`：

- 容载比；
- 源荷比；
- 电量渗透率；
- 最大供电能力的概念定义；
- CRF等通用经济公式。

只有进入正式数学优化模型，并且确实需要区分不同场景/方案时，才能增加方案下标，并必须明确说明。

原则：

> **先定义物理指标，再定义不同方案下该指标的取值。**

不要把程序中的数据维度直接搬进物理定义。

# 5. 容载比公式规范

容载比是本报告最重要的公式之一，必须重点检查。

## 5.1 推荐基础形式

对于年度 \(y\)、电压等级 \(v\)，正式容载比推荐写为：

\[
R_{y,v}
=
\frac{S_{y,v}}
{P^{+}_{\max,y,v}}
\]

其中：

- \(R_{y,v}\)：年度 \(y\)、电压等级 \(v\) 的容载比；
- \(S_{y,v}\)：同一研究区域、同一电压等级的公用变压器在役总容量；
- \(P^{+}_{\max,y,v}\)：同年度、同电压等级的同步正向最大净负荷。

如上下文已经限定年度和电压等级，也可简化为：

\[
R=\frac{S}{P_{\max}^{+}}
\]

## 5.2 禁止的写法

不要因为程序包含优化路径而直接写：

\[
R(p,y,v)
\]

除非该章节已经进入优化模型并且确实需要方案索引。

不要使用类似：

`P max(p,y,v) ⁺`

这种由普通文字、Unicode上标和脚本文本拼接出来的伪公式。

## 5.3 正向与反向必须严格分开

本项目固定口径：

> **正式容载比分母采用同步正向最大净负荷。**

反向峰值不得：

- 与正向峰值取绝对值后取大；
- 替换容载比分母；
- 被称为“反向容载比”；
- 直接与容载比合成一个峰值指标。

反向功率应进入：

- 反向峰值；
- 反向持续时间；
- 设备级反向承载力；
- 反向承载缺口。

正文必须保持：

> **容载比负责描述正向容量配置，反向承载力负责校核反向功率。**

# 6. 其他核心公式规范

## 6.1 源荷比

推荐：

\[
K_{\mathrm{SL}}
=
\frac{C_{\mathrm{RE}}}
{P_{\mathrm{L,max}}}
\]

其中：

- \(C_{\mathrm{RE}}\)：同期新能源装机容量；
- \(P_{\mathrm{L,max}}\)：同期最大负荷。

必须保证分子、分母属于同一统计年度和研究范围。

如果数据年份不能闭合：

> 不计算伪精确源荷比。

不得用2026年光伏快照直接计算2021—2025年历史源荷比。

---

## 6.2 电量渗透率

推荐：

\[
K_{\mathrm{E}}
=
\frac{E_{\mathrm{RE}}}
{E_{\mathrm{L}}}
\]

其中：

- \(E_{\mathrm{RE}}\)：年度新能源发电量；
- \(E_{\mathrm{L}}\)：同期用电量。

电量渗透率属于年度电量指标，不得直接用于替代：

- 瞬时反向峰值；
- 容载比；
- 主变反向承载力。

---

## 6.3 资本回收因子

统一写为：

\[
\mathrm{CRF}(i,n)
=
\frac{i(1+i)^n}
{(1+i)^n-1}
\]

变量说明：

- \(i\)：折现率；
- \(n\)：经济寿命。

不要混用普通文本 `CRF(i,n) = i(1+i)ⁿ / ...` 与Word公式。

---

## 6.4 低正向净负荷描述阈值

如使用20%同步正向峰值作为描述阈值，应写为：

\[
0<P_t\leq0.2P_{\max}^{+}
\]

并明确：

> 该阈值仅用于描述低正向净负荷工况，不属于设备安全限值，也不作为规划措施触发条件。

# 12. “物理校核”与“指标约束”的区分

全文必须明确：

> **容载比约束 ≠ 设备物理安全约束。**

例如：

`R≤2.0`

在本研究中属于严格优化路径的附加规划比较条件。

不能写成：

> 容载比超过2.0即设备越限。

规划措施触发应优先依据：

- 正向容量缺口；
- 反向承载缺口；
- 设备运行方式；
- N-1条件；
- 网络压力；
- 其他明确物理约束。

---

# 13. “弹性”概念固定解释

本项目“容载比弹性”不得被写成：

> 放宽安全标准。

正式含义应统一为：

> 在满足设备容量、供电安全、反向承载和网络运行等物理约束的前提下，根据不同片区源荷特征、运行状态和经济代价，允许容载比在合理范围内差异化取值。

因此：

- 弹性 ≠ 不受约束；
- 弹性 ≠ 提高容载比；
- 弹性 ≠ 降低可靠性；
- 弹性 = 物理约束下的差异化规划。

- loose path。

# 15. 优化结果的逻辑自检

由于严格优化路径的可行域是弹性优化路径可行域的子集，因此在相同模型、成本和求解精度条件下：

\[
C_{\mathrm{elastic}}^{*}
\leq
C_{\mathrm{strict}}^{*}
\]

如结果出现：

\[
C_{\mathrm{elastic}}^{*}
>
C_{\mathrm{strict}}^{*}
\]

不得通过语言润色掩盖。

必须标记：

> 求解精度、候选集合、模型实现或约束一致性需要重新检查。

# 20. 文献综述润色规则

第二章修改时重点检查：

### 不要写成文献罗列

每一组文献应遵循：

> 研究方向 → 代表性方法 → 主要发现 → 对本项目的启示或局限。

### 不扩大文献结论

原文献只研究中低压网络时，不能写成：

> 已证明110 kV县域电网同样适用。

应写：

> 其时序分析思想可为本项目提供参考，但具体阈值和结论不能直接移植。

### 国内外研究差异

保持客观：

- 国外：Hosting Capacity、主动配电网、灵活性；
- 国内：容载比、最大供电能力、承载力、主配协同和工程规划。

不要写价值判断式的“国外先进、国内落后”。

# 21. 第一章语言结构

第一章优先保持以下逻辑：

1. 新能源发展背景；
2. 徐州高渗透运行问题；
3. 正向容量与反向承载两个问题；
4. 现行容载比指标的作用和局限；
5. 为什么需要差异化规划；
6. 本项目如何解决；
7. 研究范围；
8. 研究目标；
9. 技术路线。

不要过早进入：

- Python处理细节；
- 数据库字段；
- 优化器实现；
- 具体候选编号。

第一章应让非模型开发人员也能读懂。

# 22. 第三章语言结构

第三章属于实证基础章节，语言优先遵循：

> 数据来源 → 数据可用性 → 统计结果 → 现象解释 → 对后续模型的作用。

禁止顺序：

> 先给结论 → 再寻找数据解释。

每个数值结论都应能回答：

- 哪一年？
- 哪个片区？
- 哪个电压等级？
- 数据是官方年度数据还是逐时数据？
- 是否经过质量校核？
- 单位是什么？

# 25. 表格语言规则

表格应优先使用短语，不写长句。

例如：

错误：

> “这一列主要用于说明该数据未来可能在后续计算模型中作为输入。”

推荐：

> “后续模型输入”

保持：

- 单位统一；
- 小数位基本一致；
- `110 kV`而不是`110kv`；
- `MW`、`MVA`、`h`统一；
- 负号使用数学负号或统一半角符号；
- 跨页表头重复；
- 表题与正文编号一致。

# 27. 删除AI式冗余表达

重点清理：
