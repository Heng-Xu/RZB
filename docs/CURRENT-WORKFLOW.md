## 核验及重建

使用 Conda 环境 `xuzhou110kv_clr`。本机可直接调用 `/home/xh/anaconda3/envs/xuzhou110kv_clr/bin/python`；新环境安装 `tools/requirements-current.txt`。构建还需要 Pandoc、Node.js、LibreOffice 和指定字体，进入 `研究报告/05_review/当前版` 后执行 `npm install` 安装 MathJax。可通过环境变量 `XUZHOU_LIBREOFFICE` 指定本地 soffice 路径。

```bash
# 对现有成果作完整核验，不覆盖 Word
python tools/build_current_report.py --check-only

# 修改六章源后，重建 Word 和内部 PDF，并核对实际目录页码
python tools/build_current_report.py --rebuild

# 仅为现有 Word 刷新内部排版 PDF
python tools/build_current_report.py --pdf-only

# 维护模型代码时，执行当前相关测试
python -m pytest -q 实验/研究/rebuild_2026/tests
```

重建依次装配六章源、生成原生OMML Word、制作数学排版副本、导出内部PDF、刷新目录缓存并再次导出，最后校核模型、25200组外推，重新逐格比较当前Markdown与Word数据表，并核对文档一致性。表格记录在 `05_review/当前版/Word表格内容复核.json`，不复用1003历史表格哈希。核验包括各级标题完整性、装配源文件哈希、46项目录实际页码、90张数据表、14幅图和232处原生数学对象。核验结果写入 `05_review/当前版/最终核验.json`，正式Word始终保留原生可编辑公式。LibreOffice输出保存至同版 `PDF导出日志.txt`。 当前版面抽查记录还与PDF哈希绑定；重建后若记录失效，应先渲染检查变动页及相关图表，再据实际查看结果更新 `1004二轮审查/版面抽查记录.json`，最后运行 `--check-only`。不得只替换哈希来沿用未查看过的新PDF。

当前数据保留原精度。不要将正文、图件或工作簿的两位小数显示值回填求解。重新寻优使用 `05_review/当前版/统一起点情景.py --output <独立目录>`，通用外推使用 `通用参数外推.py`；这两项会实际求解，普通文字修改无需重算。图件刷新脚本支持独立输出目录，替换前检查字体、数值及正文图名。

本轮费用参数在 `current_economic_assumptions.py` 集中定义，当前报告脚本采用40/40/25年寿命及分别计取的维护费率。联合求解支持 `--resume` 和 `--capacity-warm-start`，断点仍须通过当前约束与费用验证。费用及容量偏好阶段分别按1.00%、0.50%求解精度核验，最后固定设备布局求最少连续转接。不得将未达精度的候选解替换为最终结果。

重新计算后依次运行 `刷新费用与案例结果.py`、`更新矩阵与逐站分析.py`、`刷新图件精度.py`，再运行 `语体复核1003.py` 和构建入口。同步输出目录时删除新结果中已不存在的旧生成CSV，避免零项目方案误读上轮文件。`规划档位矩阵.py`生成108行总矩阵、432行结构分列、主选/覆盖档、完整计算范围和热力图。重新生成外推结果后，还应复算 `驱动因子分析.py` 及 `1004二轮审查/二轮技术复核.py`，核对参数作用和下限诊断。参考上限按完整精度向上归档；案例与五站模板分别保留。原反馈、语料及上一轮处理登记在 `05_review/当前版/1003反馈修订`；当前未解决问题及21条批注状态见 `1004二轮审查/二轮审查与修正说明.md`。当前结果仍有突破/排序约束、静态储能与等效转供、数据单位和截断评价期等限制，不能以通过自动核验代替工程可实施性及突破必要性验证。

改稿后核对各章连续性、引文对应、公式解释和表格居中，再更新当前状态并提交 Git。历史恢复应在单独目录或 worktree 进行，不覆盖正在维护的基线。
