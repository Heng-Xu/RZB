# 当前报告维护流程

当前有效约束为根目录及研究报告目录的 `AGENTS.md`。正式源是六章Markdown、计算表及生成段落JSON；不要从历史正文快照恢复覆盖。环境使用 `/home/xh/anaconda3/envs/xuzhou110kv_clr/bin/python`。

1. 局部调整预测表与推荐分档时，通过`tools/sync_current_report_results.py`同步资产；预测取值由`tools/report_forecast_display.py`只读提取，推荐带由`tools/report_matrix_display.py`按原容量下界衔接，原始节点包络另行归档。后续案例更新先运行`tools/verify_future_case_results.py`，核对`研究报告/01研究推荐/当前版/后续报告案例采用版本.json`及指定结果的锁定清单。原八组历史采用结果继续由`tools/verify_adopted_report_results.py`核对；当前案例的同步入口为`tools/report_annual_update.py`，`tools/sync_current_report_results.py`已衔接该入口，图件入口为`tools/refresh_annual_report_figures.py`。同步只读取固定结果，绘图CSV、矢量原件和来源哈希归入既有来源目录。若涉及小时数据，运行 `tools/prepare_regional_profiles.py`，核对补值日志和区域峰段。实际年度相关分析运行 `tools/prepare_case_correlations.py`，从原始Excel分别提取两地区年度样本；样本和系数继续在核验资料中复算，实际年度相关表按用户要求退出正文。
2. 本轮执行`python tools/report_annual_update.py`只读同步锁定年度案例，图件由`tools/refresh_annual_report_figures.py`更新。执行`python tools/build_current_report.py --feedback-report --rebuild`，先查六章源并装配核验清稿，再由`tools/revise_report_in_place.py`在10.17甲方原文件包内以xh增量修订，保留全部批注及甲方已有修订，核对接受和拒绝本轮修订视图。禁止用清稿覆盖甲方原文件。
3. 在WPS打开新Word，更新全部域并导出PDF。执行 `python tools/build_current_report.py --accept-wps-pdf <PDF路径>`，按实际标题页回填目录缓存。
4. 重新打开更新后的Word，再次导出并接收，直到目录页码、正文页码和链接目标一致。PDF必须由原生Word经WPS输出，不能以公式图片副本替换。
5. 查看目录、改动页、长公式、相关图表及分页，记录本次实际观察结果。执行 `python tools/build_current_report.py --check-only`，完成自动约束、逐格表格、原始计算和Word/PDF一致性核验。
6. 更新 `memory/current.md` 及本轮修订说明；清理失效资料后Git提交。保留用户原有 `prompt.md` 内容，并按最新要求纳入提交。

自动约束由 `tools/report_policy.json` 定义，检查入口为 `tools/check_report_policy.py --stage source|docx|final`。装配器直接调用前两阶段，交付核验调用最后阶段。版本管理前运行全部检查；不能用修改哈希或计数绕过失败。

源稿规则仅处理可客观定位的问题，不代替编辑复核。新增常见问题时，应同时修复正文、生成脚本和检测规则。长期规则只保留一份有效状态，历史条目归档，不继续追加矛盾规则。

排除式说明按章节检索并逐段判断，覆盖实际引用的生成段落及表注。修订记录保留段落前后对照，以及实质约束、数据缺口等否定表述的保留理由；检查器报告源文件行号和JSON键名。`tools/test_report_prose_policy.py` 验证问题示例、必要表述及嵌套引用定位，Git提交和CI同步执行。

讨论稿以用户指定的`研究报告/甲方反馈/10.11/供电公司讨论稿.docx`为修改对象，先备份并登记哈希，再直接以修订模式增改，修订人为`xh`，保留已有批注和未涉及段落。5.1完整复用研究报告3.5的正文、五个小节、11张表及原生行内公式，章节号、表号和引文编号按讨论稿顺接，外部章节及公式引用明确指向研究报告；复用内容逐节点核对，新增报告样式采用独立名称，原有样式保持。表1直接复用研究报告中的两地区逐年容量及措施表，区分年末配置、累计联络和当年新增工程。正文统计说明须有表中数据支撑，当前只介绍Pearson，Spearman原始核验留在资料中。设备寿命与评价期仅改文字。禁止由旧模板重新生成覆盖讨论稿。讨论稿独立核对修订作者、原始包部件、批注、数据与版面；研究报告本身仍执行上述三个阶段。

图片段落和图题由装配器显式清零点值、字符及悬挂缩进并设为居中；Word检查逐段验证，PDF检查同时验证图件实际中心位置。该规则在构建、提交和CI中自动启用，不依赖人工记忆。

参数结果采用独立锁定流程，入口为`tools/locked_parameter_results.py`。已确认工作簿位于`研究报告/01研究推荐/当前版/参数联合情景_20261012`，原始库位于`研究报告/试算/20261012_参数联合情景锁定`；来源与核验归入各自标准目录。默认核验文件哈希、从原始库复算相关与矩阵、回算设备费用，并核对来源CSV及工作簿；`--lp`重新检查矩阵端点和分层节点。`--export-to`与`--solve-to`只写独立空目录。锁定版不随正文构建自动覆盖，后续调整须另建经审查的版本。提交钩子与CI同时核验锁定数据。

正文采用十三项候选指标至五项推广参数的两层筛选逻辑，相关分析集中于第3.5节，组内相关和指标间关联分别呈现，并列明研究阈值、基础输入代表原则及五参数之间的相关关系。年最大净负荷平均增长率采用复合定义，实际年度相关表退出正文。原五项分档、2/4/6 h单元包络及9表432单元的原始锁定库和工作簿保留。正文查表矩阵按电缆长度占比≤10%、(10%,30%]、>30%分区，再按三个负荷分散系数列示完整源荷与转供区间。时长集合及端点条件仅在核验资料登记，推荐矩阵相关正文与图表不展示该参数。典型转供对照继续展示完整细节点，分别说明存量设备与重新选配条件，不独立按线路系数分类。研究报告本轮在10.17甲方原文件上增量修订，讨论稿继续在其当前原文件上增量修订，已有修订和批注保持；本轮修订显示日期按用户指定的10月18日08:00—09:00和10月19日08:00—15:00设置，实际操作时间及逐项映射另行记录。设备寿命和评价期只修改内容表述。

后续报告的区县案例固定采用`逐年需求驱动2035_20261017`，阅读入口为`研究报告/01研究推荐/当前版/后续报告案例采用版本.json`。市区、邳州2021—2035年各采用刚性`rigid`与主表弹性`elastic_capacity`，经济对照`elastic_engineering`独立保留。2021固定原表地区容量，2022—2035承接上年设备并按当年源荷求解，同一原主变位置全期最多更换一次；其配套费用优先规则、转供限制和费用条件均随该版锁定。后续调整另建版本并经用户确认。案例同步同时维护六章、图表、原文件修订稿及核验清稿，执行源稿、原生Word、WPS PDF三阶段检查；本轮记录集中于`1017甲方批注与逐年案例更新`。现有`报告数据采用版本.json`及`报告采用数据说明.md`保留为已交付报告的复现依据；参数库、相关分析及推广矩阵沿用各自确认登记。讨论稿继续保留其原定稿内容及采用原件，后续修改仍遵守增量修订要求。

当前正式报告的数据核验入口为`tools/verify_current_report.py`，逐项比对4组逐年案例、60条年度记录、46站分析、完整查表矩阵及典型转供对照，并核验原文件批注和修订视图。定稿数据继续由`tools/verify_adopted_report_results.py`独立核验并接入提交与CI。`tools/verify_report_release.py`核对本轮逐段复核、修前原件及三阶段交付证据；历史初步定档按原件和本轮独立核验衔接，不能仅更改原定档哈希。`tools/build_current_report.py --check-only`依次检查当前约束、全部Word表格及本版数据。容量用“实际容量”，项目指标统一为“年最大净负荷平均增长率”；文献与规范原名保留。新增表达规则须有文件或JSON键定位；公式控制字符和Pandoc数学转换失败均阻止构建。初步定档清单登记交付文件、六章源、维护入口及保留复现依据的哈希。历史清理按依赖核对、逐文件备份及SHA256校验、移出无关文件、完整交付核验的顺序执行，`tools/manage_preliminary_archive.py`在提交与CI检查清理清单和保留资料；本地备份被Git忽略，Git旧历史保持。

讨论稿当前内容及局部修订入口为`tools/revise_current_discussion.py`，完整复用检查委托`tools/revise_discussion_report_section.py`；补充图表与格式复用规则在`tools/discussion_expansion.py`，`tools/prepare_discussion_figures.py`只读锁定有效样本，生成可复用图件及逐点绘图CSV。每次以当前修订稿为基线增量修改，原批注和原修订保留，拒绝本轮新增ID须恢复本轮前最终视图，不能以作者名批量拒绝此前xh修订。新增图片只添加必需媒体和关系部件。原生检查逐格核对当前有效表格、研究报告格式属性和绘图节点；WPS版面证据登记DOCX与PDF哈希，变化后重新导出。

表述问题按“修正文与有效生成入口—归纳本地约束—新增可定位检测—正反例测试—接入既有构建及提交检查”执行。配套文件指引的检测覆盖六章源、引用生成段落/表注及讨论稿最终视图；文献引用和必要章节引用保留。`tools/test_discussion_revisions.py`覆盖甲方修订段落的局部文字修改与多行表头拒绝修订恢复，提交钩子和CI自动运行。

教师审阅执行两轮复核：事实轮对照原始资料、锁定结果、规范原件及文献对应方法和算例，文字轮逐段检查段内关系、短句拼接和正文分号。`tools/report_prose_review.py --output <JSON>`提供正文及候选的逐段定位，候选提示不作自动改写依据；说明性段落按列项需要保留分号。明确复发句式由`report_policy.json`拦截，历史事实核读记录保留在`1014事实与文字复核`，当前批注处理、年度案例和WPS证据集中在`1017甲方批注与逐年案例更新`，此前储能系数原文核读保留在`1017细节表述修正`，矩阵分区及补充文献证据保留在`1016矩阵分区与文献补充`，逐项按交付原件哈希衔接。`tools/verify_report_review.py`验证当前登记、修前原件、原始依据和逐段复核；数据入口逐项比对计算表、46站结果及原生公式。构建最终核验、Git提交和CI均执行，稿件变化后原审阅登记失效，须复核变化并更新记录。讨论稿段落局部修正在`tools/discussion_prose_overrides.json`维护，继续以xh在原文档包内写入，不接受或丢弃甲方既有修订。

修订显示日期仅在用户明确指定时使用`tools/adjust_discussion_revision_dates.py`调整，默认只预览，`--apply`才写回。脚本只更改指定作者的`w:date`，按段落和表格分组，保留原件、实际操作时间及逐项新旧映射，不修改系统时间、原作者修订或批注日期；随机显示时间不作为实际编辑过程记录。调整后重新做原生检查和WPS导出，并在确认正文、格式与全部其他包部件一致后更新审阅登记。该调整不自动应用于后续新修订。

引文统一由`tools/report_citations.py`按正文首次出现顺序编排，同处标注升序去重、重复来源沿用同号；源稿检查核对来源登记，原生Word和最终WPS PDF逐项验证标注次序、条目及一一对应关系。`tools/test_report_citations.py`覆盖缺项、倒序、重复和错配，构建、提交及CI执行。
