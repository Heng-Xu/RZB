# 历史决策：统一 CLR=2.0 仿真基线作为双方案比较底线

> **状态说明（2026-08-29）：本文件已被后续负责人终审决策覆盖，不是当前模型口径。**
> 当前 v3.2 正式模型以 2021 年实际在役资产为两条优化路径共同起点，既有容量存量豁免；严格路径只对规划期新增容量施加 Rcap 约束。`2×P2021` 仅保留为标准化反事实/敏感性分析，不作为甲方正式规划基线。历史内容保留用于解释版本演进。

- 日期：2026-08-27
- 决策状态：负责人确认，后续方案审查与重构必须遵守
- 当前实现状态：尚未修改 `AGENTS.md`、`model_contract.yaml`、代码和正式结果；待模型总审完成后统一升级，避免边审边改造成版本漂移。

## 1. 研究目的

本项目的核心比较不是简单复现历史实际容量，而是构造一个受控反事实仿真实验：从统一的传统规划基准状态出发，比较“继续刚性执行容载比 2.0”与“在满足物理安全约束前提下允许容载比弹性变化”两种规划机制的长期差异。

因此，**双方案必须从同一个 CLR=2.0 仿真基线出发**。该基线是用于方案比较的归一化反事实状态，不宣称等于任一片区 2021 年真实在役容量。

## 2. 基线原则

对片区/电压层构造统一仿真起点：

```text
R0_sim = 2.0
S0_sim = 2.0 × P0_ref
```

其中 `P0_ref` 的具体选取规则需在模型总审中进一步科学论证并冻结；可以参考现 v3.1 为防止后续负荷回落导致起点即失效而采用的基准年/决策期参照峰思路，但最终公式必须同时满足：物理含义清晰、两个方案完全共用、不可把“报告容量”与真实设备容量混为一谈。

历史实际容量、峰值和设备数据继续保留，用于：
- 数据校准；
- 历史事实对照；
- 工程候选和物理约束构造；
- 检验归一化仿真结论与实际系统的偏差。

它们不再作为双方案不同的起点。

## 3. 双方案的唯一核心差异

### 方案 A：刚性容载比规划

两个方案共享同一 CLR=2.0 仿真基线。方案 A 在决策期逐年继续施加：

```text
R_y <= 2.0
```

并同时满足全部正向、反向、储能、离散设备、站址和网络压力约束。

### 方案 B：弹性容载比规划

从同一个 CLR=2.0 仿真基线出发，不施加统一的 `R<=2.0` 上限，但仍必须满足与方案 A 完全一致的：
- 正向供电能力约束；
- 设备反向承载约束；
- 储能功率、能量、SOC 和充放电边界；
- 离散工程候选与可用年份；
- 站址/间隔条件；
- 网络压力和其他证据门禁。

因此，两方案的实验控制变量应尽量收敛为：**是否维持统一 CLR≤2.0 刚性约束**。

## 4. 比较结果的科学意义

在共同基线、共同候选、共同物理约束和共同成本库成立后，两方案的以下结果才具备直接比较意义：
- 2022—2025 各年度建设措施；
- 主变容量演化；
- 储能规模与投运时序；
- CAPEX；
- 累计在役 EAC；
- 最终 CLR；
- 正向容量裕度；
- 反向承载裕度；
- 可行性和措施触发原因。

此时才允许将：

```text
C_rigid - C_elastic
```

解释为在统一仿真基线下“持续执行刚性容载比约束”相对于“弹性规划”的增量经济代价。

## 5. 弹性扫描定位

保留并强化 `Rcap=1.5~3.0, ∞` 的扫描。所有扫描点也必须从同一 CLR=2.0 仿真基线出发，在相同物理与经济条件下仅改变容载比上限：

```text
Rcap -> C(Rcap)
```

该前沿用于识别：
- 刚性控制开始显著增加成本的阈值；
- 成本跳变/措施翻转区间；
- 近优带；
- 分片区推荐容载比范围。

## 6. 对当前 v3.1 的影响

当前 v3.1 存在“弹性方案从 2021 实际状态出发、严格方案从 CLR=2.0 归一状态出发”的不同比较基线，因此：
- 现有两方案累计年化成本跨口径不可比的限制，在当前结果版本中仍然有效；
- 当前正式结果和报告不能在模型重构前直接改写为可比；
- 后续总审完成后，应统一升级契约、实施计划、规格、测试、规划器、结果矩阵和报告；
- 应尽量取消“物理容量一套、报告容量另一套且仅后者受 CLR 约束”的混淆设计，把归一化状态明确建模为统一的反事实仿真起点。

## 7. 后续实施纪律

1. 先完成整个模型科学性总审，继续寻找其他结构性问题；
2. 总审结束后形成新的模型版本设计，不逐点零散打补丁；
3. 再按“失败测试 → 契约/规格 → 实现 → 单元测试 → 端到端 → 正式结果 → 报告”的顺序统一重构；
4. 在新结果全量验证完成前，v3.1 正式结果只作为旧基线证据，不与新口径混用。
