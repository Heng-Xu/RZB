# 研究报告终稿写作与科学表达硬约束

本文件是终稿构建的强制质量合同。凡修改终稿Markdown、生成Word/PDF或自动集成专题内容，均必须满足以下要求。

## 1. 三项不可降级原则

- **语言逻辑连贯**：每一节必须围绕明确问题展开，段落之间有自然承接，方法、数据、结果和工程解释形成完整逻辑链。
- **术语科学准确**：术语、变量、量纲、约束对象、数据证据等级和模型边界必须与项目正式模型一致，不得为了简化表述改变科学含义。
- **符合人类阅读习惯**：采用甲方可直接阅读的正式工程研究报告语言，避免内部开发口吻、AI式套话、机械堆砌和碎片化短句。

## 2. 对外正文强制口径

正文应优先采用自然中文专业表述。研究过程中的内部治理、脚本、代码、版本和自动化信息不得进入甲方正文。

以下表达原则必须保持：

- 实际物理容载比是规划结果指标；Rcap是规划期新增变电容量控制参数。
- 既有资产执行存量容量豁免，Rcap只约束规划期新增容量。
- 反向潮流与正向容载比分开建模。
- 正式经济目标为“2022—2025年规划期累计在役等年成本”，单位为万元。
- 110 kV线路指标统一称“110 kV线路统计负载余度”，仅作容量压力筛查。
- 推荐矩阵统一称“弹性容载比样本支持参考矩阵”；同样本构建与查询只能称“样本内一致性检查”。
- 当前样本不足以形成具有外推能力的连续四维区间，不人为补造推荐上限。
- AHP无经确认专家判断矩阵时不生成具体权重，不改变正式Rcap优化结论。
- 10 kV专题为规划级“分段—联络拓扑容量重构”分析，不表述为完整交流潮流、短路或继电保护定值结论。
- “反向潮流≤80%”仅用于甲方给定的反向潮流专题控制场景，不用于普通正向负荷转供。

## 3. 禁止进入甲方正文的表达

包括但不限于：

- GitHub Actions、artifact、manifest、pipeline、fallback；
- 脚本路径、CSV字段名、任务ID、提交SHA、运行ID；
- “正式v3.2模型”“二次科学审查表明”“冻结结果”“脚本验证通过”“程序已复现”等内部过程性表述；
- 无数据支撑的“显著提升”“全面领先”“充分证明”“具有重要意义”等泛化结论；
- 将统计筛查量误写为完整潮流安全结论，或将规划级可行性误写为现场操作结论。

## 4. 可读性最低门槛

- 图、表、公式必须有正文引入，关键结果必须有解释。
- 不允许超长、失去主谓宾关系的句子；一个句子原则上只承担一个主要判断，必要时拆分。
- 不允许以连续短句、标签式语句代替正式段落。
- 同一概念在全文采用统一名称，不在“容量裕度/支撑裕度/线路余度”等近义词间随意切换。
- 结论必须回答“得到什么结果、为什么、对规划有什么含义”，不能只重复表格数值。

## 5. 构建门禁

终稿自动构建必须先执行：

`python 实验/研究/scripts/check_report_writing_quality.py --markdown <终稿MD> --contract 研究报告/终稿/写作与科学表达硬约束.md`

检查失败时，构建流程必须失败，不能生成并提交新的正式Word/PDF成品。

自动检查是最低门槛，不替代提交甲方前的人工逐章通读。
