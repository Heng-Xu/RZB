# 既定远景工程清单的逐年分期建设

用户认可上一轮总体方向，但认为2022首年弹性净增市区803MVA、邳州442.5MVA过于集中。本轮调整建设投运时序，保留2021原地区容量、全部逐小时源荷输入、共同容载比下限、20%站级转供限额和经济参数。

每个地区、每个方案分别使用上一版2035主变配置作为远景工程清单，工程逐台投运、全期只更换一次。各年按预测负荷的五年期增长趋势确定累计建设进度，容许50MVA整台工程余量，每年净增容量不超过上年5%。刚性继续服从2.0新增容量控制；终年主变逐站配置与上一版相同。5%和50MVA为本轮排程研究假设，不作为标准强制数值；实际历史负荷有升有降，未改成趋势线。

本轮确定的是既定主变清单的年度建设安排，储能、联络和固定事故预案逐年重新选配。新增配套按上一轮原规则逐年保留，因此分期可能增加费用。目标与求解记录均按条件排程问题解释，不宣称全期联合全局最优，也不把曲线美观当作安全约束通过的依据。

采用结果：研究报告/试算/20261017_分期建设排程逐年2035/{city,pizhou}/{rigid,elastic_capacity}。此前仅加5%年度上限的试算保留在20261017_分期增容逐年2035，未采用为本轮排程结果。

项目根目录使用xuzhou110kv_clr环境，OPENBLAS_NUM_THREADS=1：

1. `python -m 实验.研究.rebuild_2026.annual_phased_2035_20261017.prepare`
2. `python -m 实验.研究.rebuild_2026.annual_phased_2035_20261017.run --region city --case rigid --seconds 8`，邳州改pizhou。
3. `python -m 实验.研究.rebuild_2026.annual_phased_2035_20261017.capacity --region city --seconds 8`，邳州改pizhou。
4. `python -m 实验.研究.rebuild_2026.annual_phased_2035_20261017.verify`
5. `python -m 实验.研究.rebuild_2026.annual_phased_2035_20261017.export`
6. `python -m 实验.研究.rebuild_2026.annual_phased_2035_20261017.spotcheck`
7. `python -m 实验.研究.rebuild_2026.annual_phased_2035_20261017.audit`
8. `python -m 实验.研究.rebuild_2026.annual_phased_2035_20261017.test_model`

交付保留两地区2021—2035逐年左右对照：刚性左、弹性右。分期影响另列原方案、当年净增、期末容量、建设年份数和费用变化。核验从原始整数解重建全部约束，检查每年工程量与终期清单，另直接校核全年8760小时正常及逐站N-1工况。2021固定基线原缺口单列。候选接线和源荷区段仍为代理，储能仍采用静态持续时间模型。
