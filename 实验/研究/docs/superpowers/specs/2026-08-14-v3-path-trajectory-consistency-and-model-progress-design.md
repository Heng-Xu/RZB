# v3 最终路径轨迹一致性修复与建模进度底稿设计

日期：2026-08-14  
状态：用户已批准，进入实现  
适用范围：`real_2021_2025` v3 正式生产链及 `研究报告/建模进度/` 底稿

## 1. 问题与结论

当前冻结的共同基准、三路径、正式容载比、物理约束、离散候选和累计在役 EAC 目标没有发现业务定义冲突。已确认的问题位于多年度动态规划的结果写出层：

- `path_cost_breakdown.csv` 和 `path_action_results.csv` 使用 2025 年最终最优状态；
- `path_year_results.csv` 在每个年度写入当时成本最低的滚动前缀状态；
- 当最终最优路径需要在早期选择“当年略贵、但后续年度可持续可行”的离散措施时，两类状态不相同；
- 因此 110 kV 严格路径的部分年度容量、储能柜数、年度 CAPEX、年度在役 EAC 和累计在役 EAC 与最终动作表不一致。

该问题不改变最终主矩阵采用的最终最优成本，也不改变严格路径是否可行或 `R<=2.0` 的业务定义，但会使逐年技术附表不能作为同一条最终路径的可追溯轨迹，必须先修正再撰写报告。

## 2. 修复方案

保留现有动态规划的状态搜索和最终目标函数，不改变候选集合、物理检查或成本计算。对最终可行的每个“片区—电压—路径”组：

1. 完成 2022—2025 动态规划后选出 2025 年最终最优状态；
2. 从该状态保存的最终动作列表反推各动作的投运年份；
3. 对每个年度重建截至该年的候选掩码、累计储能柜数和在役动作；
4. 使用原 `_evaluate_state` 重新计算该年度容量、正向峰值、反向峰值、缺口和容载比；
5. 由同一最终动作列表计算年度 CAPEX、年度在役 EAC、累计 CAPEX和累计在役 EAC；
6. 断言 2025 年逐年表累计 EAC 等于成本分解表最终累计 EAC。

最终不可行的 35 kV 严格路径保留显式不可行记录，不用连续虚构容量或跨电压措施强行补齐。

## 3. 测试设计

新增最小单元场景：2022 年较小退役候选当年成本更低，但无法满足 2023—2025 严格约束；较大退役候选在 2022 年略贵，却是唯一可延续到 2025 年的最终路径。修复前测试必须证明逐年表误写较小候选，修复后必须满足：

- 最终动作表选择较大候选并在 2022 年投运；
- 2022—2025 逐年容量均对应较大候选；
- 年度在役 EAC 持续计入；
- 累计 EAC 为年度在役 EAC 的逐年累加；
- 2025 年逐年累计 EAC 与成本分解表一致。

真实生产数据另做跨表回放检查：最终可行路径的逐年容量、储能柜数、年度 CAPEX、年度在役 EAC 和累计 EAC 均能由最终动作表复算，误差不超过 `1e-6`。

## 4. 报告交付设计

修复、全量测试和真实端到端验证通过后，生成单一主文件：

`研究报告/建模进度/当前建模进度与阶段成果总结_v3.md`

文档采用技术受众、回答优先的结构，只使用文字和 Markdown 表格，不制作图片。主要章节为：

1. 当前结论与成果摘要；
2. v3 冻结口径和研究边界；
3. 阶段 0—7 完成情况及证据；
4. 数据源、映射、年度资产和质量处理；
5. 指标、物理约束、离散动作和成本模型；
6. 2022—2025 联合优化方法；
7. 110 kV 八县区正式结果；
8. 35 kV 八县区辅助结果；
9. QX-00005 最终路径逐年轨迹和措施成本；
10. 测试、端到端与成果清单；
11. 数据限制、证据等级和甲方解释；
12. 早期合成方法验证与当前真实数据模型的边界；
13. 后续研究报告章节映射及可复用表述；
14. 文件证据索引。

精确数字以修复后正式 CSV/Markdown 为准。早期 `real_2025`、旧年度矩阵、IEEE33 合成算例和旧 EA 结果仅说明方法演进，不作为当前 v3 结果。
