# v3 最终 Word 矩阵展示优化设计

**日期：** 2026-08-14  
**适用范围：** `real_2021_2025` v3 正式运行产物  
**设计状态：** 已获用户批准，待书面规格审查  
**关联规范：** `docs/WORD-MATRIX-PRESENTATION-SPEC.md`、`docs/PROJECT-OUTPUT-CONVENTIONS.md`

## 1. 目标与不变边界

本设计只优化 Word 的人工审查和甲方汇报展示，不改变模型、数据、路径、成本目标、约束起点、设备电压归属或正式查值源。

必须保留以下冻结边界：

- 2021 年实际状态是共同基准，决策期为 2022—2025 年，成本统一按 2025 年价格计价。
- 正式路径只显示 `PATH_ACTUAL_2021_2025`、`PATH_OPT_CLR_UNBOUNDED` 和 `PATH_OPT_CLR_LE_2`，不出现旧 `SCHEME_C0/A/B`。
- 110 kV 输出正式推荐矩阵，35 kV 输出辅助矩阵；不得跨电压合计容量、负荷、光伏或成本。
- Word 采用转置式矩阵：第一列为中文指标，后续列为脱敏片区；CSV/Markdown 仍是精确查值源。
- QX-00005 三路径逐年轨迹、年度动作、成本分解和物理回放继续放技术附表，不制作五张年度正式 Word 矩阵。
- 主表不放机器字段、哈希、JSON、候选编号、源列号或长备注；数据问题集中引用《v3 真实数据问题补充说明（供甲方汇报）》。
- 正向容载比、反向峰值和反向承载缺口分开显示；实际路径成本为“未识别”时不得显示为 0。
- 不使用图片、图表或截图作为 Word 主表内容。

现有文件名保持不变，避免破坏下游脚本和查值链接：

```text
results/runs/real-2021-2025-contract-v3/<run_id>/

├── county_110_recommendation_matrix.docx
├── county_35_recommendation_matrix.csv

├── path_year_results.csv

├── qx00005_path_validation.csv
├── 内部容量网络压力检查.csv
├── 问题台账.md
└── manifest.json
```

职责划分如下：

| 层级 | 文件 | 职责 |
| --- | --- | --- |
| 精确查值层 | 两套推荐矩阵 CSV | 保存机器字段、原始数值、质量标记和可复算字段 |
| 汇报审查层 | 两套推荐矩阵 DOCX | 提供中文化、分组、格式化和打印友好的人工审查表 |
| 技术证据层 | `path_*.csv`、`qx00005_path_validation.csv`、网络筛查表 | 保存年度轨迹、动作、成本、SOC/物理检查和容量网络筛查 |
| 解释层 | `实验/研究/分析/v3真实数据问题补充说明_供甲方汇报.md` | 集中解释映射、异常、缺失、未识别成本、不可行和证据等级 |

Word 生成器只能消费已验证的矩阵 DataFrame，不得在 Word 层重新计算容载比、成本、缺口或推荐措施。

## 3. Word 页面结构

110 kV 和 35 kV 各生成一个独立 DOCX，版式一致但标题和提示语不同。

### 3.1 页面设置

- 纸张：A4 横向。
- 页边距：上、下 1.25 cm，左、右 1.20 cm。
- 表格宽度固定：指标列约 5.2 cm，8 个片区列均分剩余宽度。
- 表头跨页重复；禁止将一个片区列拆到下一页。
- 表格允许跨 2 页，但不产生横向溢出；表前说明和表后说明不得被孤立到空白页。
- 页脚显示“v3 真实数据｜Word 人工审查层｜精确查值以同目录 CSV 为准”和页码，不显示哈希。

### 3.2 字体与颜色

- 主标题：黑体，16 pt，加粗，深蓝色 `#17365D`。
- 副标题和说明：宋体，9 pt，深灰色 `#404040`。
- 表格正文：宋体，8.5—9 pt；数字和英文使用 Arial 或 Times New Roman。
- 表头：白色加粗字体，深蓝底色 `#1F4E78`。
- 分组行：白色加粗字体，浅蓝底色 `#D9EAF7`。
- 推荐结果行：浅绿色 `#E2F0D9`，只用于已形成推荐的结果，不用于 35 kV 严格路径不可行状态。
- 严格路径行：浅黄色 `#FFF2CC`。
- 不可行、未形成唯一推荐：浅红色 `#FCE4D6`，文字使用深红色。
- `EVIDENCE_C` 或明确证据缺口：浅橙色 `#FCE4D6`；不得用绿色暗示证据充分。

颜色只用于人工定位，不改变任何数值或状态。所有状态仍必须以中文文字直接写出。

## 4. 主矩阵内容与行顺序

表格首行为：`指标`、`片区01` 至 `片区08`。片区显示使用脱敏编号，不在 Word 主表显示 `QX-xxxxx`。

行分为 6 个视觉分组，组名使用全宽浅蓝分组行；分组行不是数据字段，不替代指标列。

### 4.1 口径与推荐结论

1. 资产范围
2. 证据等级
3. 推荐容载比区间
4. 推荐容载比中心值
5. 措施触发约束
6. 推荐措施

其中，推荐中心值必须来自不限制容载比路径的成本最小可行结果；推荐区间必须使用已验证的敏感性结果形成。若源数据没有形成中心值或区间，不得用区间端点或人工估算补齐，显示“未形成推荐”。

推荐区间有效样本数和形成方法单独放入“推荐区间依据”分组，避免与片区推荐措施混在同一行，同时保留区间形成的可审查证据。

### 4.2 2025 年容载比

7. 2025 年容载比｜2021—2025 实际（事实对照）
8. 2025 年容载比｜不限制容载比优化
9. 2025 年容载比｜控制容载比不超过 2.0 优化

严格路径不可行时显示“不可行”，不得显示空白、0 或上一条路径数值。

### 4.3 累计年化成本

10. 累计年化成本｜2021—2025 实际（事实对照）
11. 累计年化成本｜不限制容载比优化
12. 累计年化成本｜控制容载比不超过 2.0 优化
13. 严格约束增量成本

金额统一使用“万元”，保留 2 位小数并使用千位分隔。实际路径设备级动作未闭合时显示“未识别（设备动作成本未闭合）”，绝不显示为 0。

### 4.4 设备与负荷口径

14. 公用变容量（MVA）
15. 正向最大净负荷（MW）
16. 反向峰值（MW）

这 3 项必须来自已审批的同电压年度口径或已明确的路径结果。若反向同步峰值没有形成正式证据，显示“未形成同步反向峰值”，不得将静态站级极值相加或以 0 代替。

### 4.5 缺口与设备数

17. 正向容量缺口（MW）
18. 反向承载缺口（MW）
19. 正向缺口设备数
20. 反向缺口设备数

缺口保留 2 位小数；设备数使用整数。缺口为 0 时显示 `0.00` 或 `0`，不能用“无数据”替代真实的零缺口。

### 4.6 表后边界说明

主表下方固定放置 4 条说明：

1. 正式容载比只使用同电压等级公用变容量除以该路径、该年度同步正向最大净负荷；反向峰值和反向承载力单列。
2. 110 kV 为正式推荐矩阵；35 kV 为辅助矩阵，不形成 110 kV 正式唯一推荐。
3. Word 为人工审查层，精确查值以同目录 CSV/Markdown 为准；“未识别”不等于 0，“不可行”不等于缺失。
4. 数据映射、异常值、历史范围、成本闭合和跨年光伏快照的解释见 [v3 真实数据问题补充说明](../../../分析/v3真实数据问题补充说明_供甲方汇报.md)。

## 5. 字段中文化和状态规则

Word 层使用字段注册表，不直接把 CSV 字段名写入主表。

| 机器值 | Word 显示 |
| --- | --- |
| `PATH_ACTUAL_2021_2025` | 2021—2025 实际（事实对照） |
| `PATH_OPT_CLR_UNBOUNDED` | 不限制容载比优化 |
| `PATH_OPT_CLR_LE_2` | 控制容载比不超过 2.0 优化 |
| `EVIDENCE_A/B/C` | A 级 / B 级 / C 级 |
| `operating_2025` | 2025 年运行口径 |
| `storage` | 储能 |
| `new_third_transformer` | 新建第三台主变 |
| `none`、`无` | 无 |
| `positive_capacity_gap` | 正向容量缺口 |
| `reverse_hosting_gap` | 反向承载缺口 |
| `positive_capacity_gap;reverse_hosting_gap` | 正向容量缺口、反向承载缺口 |
| `none`（触发约束） | 无缺口触发 |
| `不可行` | 不可行 |
| `未识别` | 未识别（设备动作成本未闭合） |

多项措施按中文顿号连接；未知动作不得原样暴露机器代码，统一显示“未形成唯一推荐”，并在问题说明中保留原始值和解释。

## 6. 110 kV 与 35 kV 的差异化展示

### 6.1 110 kV

标题为“110 kV 县区正式推荐矩阵”，副标题标明“8 片区｜正式推荐｜2021 年共同基准｜2022—2025 年决策期”。推荐容载比和推荐措施可以使用浅绿色突出，但不得把容载比大于 2.0 本身写成自动扩容触发原因。

### 6.2 35 kV

标题为“35 kV 县区辅助矩阵”，表前增加橙色边框提示：

> 本表为 35 kV 辅助分析，不替代 110 kV 正式推荐。严格路径当前不可行的片区，不形成正式唯一推荐；设备明细、候选闭合和成本范围以技术附表为准。

35 kV 严格路径不可行的单元使用浅红色和“不可行”文字，不使用绿色推荐色；不得把 35 kV 辅助结果写成县区总量正式结论。

## 7. 生成和数据流

生成顺序固定为：

```text
已验证的 v3 矩阵 DataFrame
        │
        ├── CSV 原样写出（精确查值层）
        │
        └── 字段注册表、格式化器、状态样式
                    │
                    └── DOCX 转置矩阵（人工审查层）
```

生成器必须：

- 只从矩阵字段读取数据，不从 Word 文本反推数据；
- 在写出前检查 8 个唯一片区、单一电压等级、路径名称和必备指标字段；
- 对缺少的正式指标字段直接失败并报告字段名，不能静默少行；
- 对 `NaN`、`不可行`、`未识别`、`未形成推荐` 使用显式中文状态；
- 保持 CSV、DOCX、manifest 的同一批次和哈希关系；
- 不改变现有两个 DOCX 文件名和 manifest 文件名。

主表中需要展示但当前矩阵尚未直接暴露的容量、正向峰值、反向峰值和推荐中心值，应由上游 v3 矩阵构建阶段从已验证结果补齐；禁止在 Word 层用静态极值、区间端点或跨电压数据代替。

## 8. 测试与验收

在现有契约测试和全量测试之外，新增 Word 展示层断言：

1. DOCX 包含 `styles.xml`、页面方向为横向、A4 页面尺寸、页边距和页脚信息。
2. 两套 DOCX 均只有一张主矩阵表，且表头为“指标、片区01—片区08”。
3. 主表不出现 `QX-`、`SCHEME_`、`source_sha256`、`candidate_id`、JSON 或机器字段名。
4. 主表包含 6 个分组、规定的路径中文名、推荐区间、三路径 2025 年容载比、三路径累计年化成本、严格约束增量成本、缺口、设备数、推荐措施和证据等级。
5. 110 kV 文档含“正式推荐”提示；35 kV 文档含“辅助矩阵”和“不可行不形成正式唯一推荐”提示。
6. 实际路径“未识别”不被格式化成 `0.00`；严格路径不可行不被格式化为空白或数字。
7. 生成后的 CSV 内容与原矩阵数据逐字段一致，Word 只改变标签、格式和状态显示，不改变数值。
8. 运行 v3 全量测试、真实端到端入口和 Word 结构检查后，重新计算 manifest 哈希并检查两路径累计年化成本包含关系、严格路径逐年 `R≤2.0`、110/35 kV 分离和质量标记。

验收通过的含义是“展示层完成”，不改变 v3 模型的完成声明门槛；所有最终交付仍需同时具备两套矩阵、技术附表、问题台账和 manifest。

## 9. 非目标

- 不恢复旧 `real_2025`、旧年度矩阵或旧 C0/A/B Word。
- 不新增图片、图表或视觉分析产物作为主表内容。
- 不把 110 kV 与 35 kV 合并到一个可排名矩阵。
- 不在 Word 生成阶段重新求解、重新映射、重新估算成本或修正异常值。
- 不通过删除“未识别”“不可行”状态来制造完整性。
